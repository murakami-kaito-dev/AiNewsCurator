## [済 2026-08-27] ニュースレターの「配信」+ ダブルオプトイン(確認メール)

**実装済み**(newsletter/2026-08-27)。送信=Brevo(無料300通/日・要ユーザーのアカウント接続)。
仕組み: /api/subscribe(pending+確認メール) → /api/confirm(確定) → /api/unsubscribe(解除・全配信メールに記載)。
配信はWorkerのcron(毎朝7:30 JST)が新しい号を検知してconfirmed宛に送る(エージェントは無変更)。
残: (a)ユーザーのBrevo接続(APIキー+送信元検証→CF SecretsにBREVO_API_KEY/SENDER_EMAIL) (b)到達率向上のための独自ドメイン認証(任意)。
以下は当時の記録:

### (旧)

- **記録日**: 2026-08-22
- **なぜ必要か**:
  現状 `/api/subscribe`(worker/index.js)は、登録メールを KV `SUBSCRIBERS` に**集めるだけ**。
  次の穴がある — ①タイプミス(`gmial.com` 等)や②他人のアドレスや③存在しないアドレスでも、
  形式が正しければ登録できてしまう。さらに④実際に読者へ**配信する手段が未実装**。
- **今すぐやらない理由**:
  まだ送信していないので、間違ったアドレスが混じっても実害が小さい(眠っているだけ)。
  読者数もほぼゼロで、対策の費用対効果が今は低い。
- **対応内容(配信を始める前に必ず)**:
  1. **メール送信手段の接続**(例: Resend / Amazon SES / MailChannels 等)。
     到達率のため独自ドメインがあると望ましい([[deploy-guide]] の独自ドメイン項と関連)。
  2. **ダブルオプトイン(確認メール方式)**:
     - 登録時に確認メールを送り、リンククリックで確定。
     - KV の値に `status: "pending" | "confirmed"` と確認トークンを持たせ、確認エンドポイントで検証。
     - これで①タイプミス②なりすまし③不達④悪用登録をまとめて防げる(業界標準)。
  3. **配信解除(unsubscribe)リンク**の用意(法令・マナー面で必須)。
  4. 併せて軽い強化: よくあるタイプミスdrドメインの指摘、短時間の大量登録へのレート制限。
  5. 理想形: **週次更新エージェントが号を自動でメール配信**するところまで接続。
- **関連**: `.claude/docs/monetization.md`(①ニュースレター)、`worker/index.js`(`/api/subscribe`)、
  KV名前空間 `SUBSCRIBERS`(id: 71605517d80c48219d92723382968667)。
