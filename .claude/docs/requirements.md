# AiNewsCurator 要件定義

作成日: 2026-08-22 / 作成者: Claude (ユーザーの要求レベルの相談を要件化したもの)

## 1. 目的・背景

ユーザー(ソロ開発者)が **AI/LLM の技術・トレンドについていく** ことを、
「キャッチアップする」という行動・アクション自体を不要にする形で実現する。

- ネットサーフィンや都度の質問といった能動的な情報収集の手間をゼロにする
- アプリを開けば、整理済み・解説済み・キュレーション済みの情報が待っている状態にする
- 同じ悩みを持つエンジニアへの「プレゼント」としての意義も持つ(ただし最優先はユーザー本人)

## 2. スコープ決定(ユーザー確認済み)

| 項目 | 決定 |
|---|---|
| 形態 | **Web (PWA) 先行**。後日 Flutter でのモバイルアプリ化を検討(両方) |
| ホスティング | 無料枠必須 → **GitHub Pages**(完全無料・自動デプロイと相性◎) |
| 自動更新 | **スケジュール済みクラウドエージェント**(Claude Code の schedule 機能)で2週間ごとに自律実行 |
| 費用 | 無料枠最優先。GitHub Pages は完全無料 |

## 3. コンテンツ要件(タブ構成)

1. **今週のトレンド** (`trends`) — 2週間ごとに自動更新されるキュレーション。
   新モデル・新ツール・業界動向。各記事に「なぜ重要か」の一言を必ず添える。
2. **AIの歴史** (`history`) — パーセプトロン〜Transformer〜ChatGPT〜現在の年表。
   固定コンテンツ + 更新のたび末尾に追記。
3. **用語・概念辞典** (`glossary`) — MCP, RAG, エージェント, ハーネスエンジニアリング,
   ループエンジニアリング等。「いつ・なぜ流行ったか」の文脈つき。検索可能。
4. **LLMのしくみ** (`mechanism`) — Transformer / Attention / 学習と推論 / RLHF 等を
   **図解・アニメーション**(SVG + CSS/JS アニメーション)で解説。理解促進が目的。
5. **現場での活用** (`in-practice`) — 実務での AI 活用事例。職種別・ユースケース別。
6. **できること / できないこと** (`capability-map`) — 現在の AI の能力境界マップ。
   更新のたび改訂(「できないこと」が「できること」に移動していく様子が見える)。
7. **次に来るもの** (`radar`) — 萌芽期の概念の早期警戒レーダー(ユーザー承認済みの追加提案)。
8. **学習ロードマップ** (`roadmap`) — どの順で理解すべきかのガイド(同上)。

## 4. 非機能要件

- **PWA**: ホーム画面追加でアプリのように使える。オフライン閲覧(Service Worker)。
- **日本語** が主言語。
- モバイルファーストのレスポンシブデザイン。ダーク/ライト両対応。
- ビルドステップなしの静的サイト(自動更新エージェントの仕事を単純に保つため):
  コンテンツは `content/*.json` に分離し、シェル(HTML/CSS/JS)は安定させる。
- 更新エージェントのフロー: Webリサーチ → `content/*.json` 更新 → commit → push
  → GitHub Pages が自動デプロイ。

## 5. 自動更新(2週間ごと)の要件

- リサーチ範囲: 新モデル/新ツール/新概念・用語/能力境界の変化/現場活用の新事例
- `trends` は新規記事を先頭に追加(過去分はアーカイブとして残す)
- `glossary` / `capability-map` / `radar` / `history` は差分更新
- 更新のたび `.claude/docs/release-log.md` に記録し、バージョン(`vYYYY.MM.DD`)を付す

## 6. ユーザーが手動で行う操作(最小化し、手順書化する)

- GitHub リポジトリ作成と Pages 有効化(初回のみ) → `.claude/docs/deploy-guide.md`
- スケジュールエージェントの承認(初回のみ)
